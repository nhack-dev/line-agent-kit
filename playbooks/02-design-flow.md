# 02 流れ（あいさつ・ステップ・タグ）を設計する

## 先にオーナーに聞く3つ

1. このアカウントに来る人は **どこから・何を期待して** 友だち追加するか（例 ブログの「無料の献立表」から）
2. 1〜2週間後に **どうなっていてほしいか**（例 相談を予約／教材を買う／ただ続けて読む）
3. 送ってはいけないこと・言ってはいけないこと（業種の決まり・誇大になりやすい言い方）

## 組み立ての型

```
0日目  あいさつ（reply・無料）… 約束したものを渡す＋これから何が届くか＋配信停止の言葉
1日目  教える便①（悩みの言い当て→小さな解決）
2日目  教える便②（よくある失敗→避け方）
3日目  アンケートの答えで分ける便（only_if_tags）
4日目  教える便③＋「詳しく見る」ボタン（buy=…）← 売り込みは軽く1回
6日目  まとめ＋質問を受ける
購入後  別シナリオ（start: tag:buyer:…）で使い方の便
```

- 1人に届く数えられる便は1日1通まで。便の間は最低1日あける
- 送る時刻はそろえる（読む時間を覚えてもらう）。迷ったら 12:00 か 19:00〜21:00
- 1通は 300〜600字。最初の1行で「何の便か」が分かるように
- タグの名前は `種類:値`（`goal:time`・`buyer:recipe-book`）。あとで絞るときに読める名前にする

## 見積もりを先に出す

```bash
python3 scripts/build_flow.py --friends <月に増える見込み>
```

例 友だちが月100人増え、ステップが6通なら約600通。コミュニケーション（200通）では足りない。
→ 便を減らす／教える便を reply で返す形（「続きは "2" と送ってください」→ キーワードで返す）に寄せる／プランを上げる、の順で考える。

## 書いたあとに確かめること

- `build_flow.py` が誤り0件
- 手元の試し（README の最初の10分）で、あいさつ → アンケート → 分かれる便 → 購入ボタン を一度ずつ通し、`logs/mock-line.jsonl` の文を読み直す
- ステップの便を早く見たいときは、手元の D1 で `UPDATE enrollments SET next_at = 1` → `admin.py run --go`
